# Трассировка проектных решений: Linear -> Figma -> Код

## Цель

Сделать проектирование проверяемым: любое важное решение должно быть видно не только в Linear/Figma, но и в репозитории.

## Минимальный pipeline

1. **Linear**  
   Создайте задачу/эпик с формулировкой проблемы и критериями приемки.

2. **Figma**  
   Привяжите к задаче конкретный файл/фрейм/прототип (если решение затрагивает UI/UX).

3. **ADR**  
   Зафиксируйте решение в ADR-файле (контекст, альтернативы, выбранный вариант, риски).

4. **Код и тесты**  
   Реализуйте изменение, добавьте/обновите тесты и привяжите commit/PR к Linear.

5. **Wiki/README (при необходимости)**  
   Обновите пользовательскую/техническую документацию.

## Чек по каждой задаче

- [ ] Есть ссылка на Linear issue/epic.
- [ ] Есть ссылка на Figma file/frame (если UI/UX).
- [ ] Есть ADR с выбором варианта и последствиями.
- [ ] Есть commit/PR со ссылкой на Linear.
- [ ] Есть обновление документации (если влияет на процесс/архитектуру).

## Рекомендуемый формат ссылок в описании PR

```text
Linear: https://linear.app/<workspace>/issue/...
Figma: https://www.figma.com/file/... (frame: ...)
ADR: шаблон проектирования/ADR-00X-....md
```
