Настройка агентов
Агенты для написания кода чрезвычайно умны и не требуют дополнительной настройки. Они хорошо разбираются в проверенных подходах к разработке программного обеспечения и в целом принимают правильные решения.

Однако они не знают, как ваша команда предпочитает писать код, какие инструменты вы используете и в каком контексте работает ваш бизнес. Здесь на помощь приходит кастомизация. Вы можете настроить агентов так, чтобы они работали эффективнее и выдавали более качественный результат.

Cursor предлагает два уровня настройки, которые соответствуют тому, как вы знакомите нового члена команды с работой: правила для того, что он должен знать всегда, и навыки для специализированных знаний, которые он может использовать по мере необходимости.

Правила: статический контекст
Rules — это файлы с разметкой, хранящиеся в .cursor/rules/, которые агент видит в начале каждого диалога. Их можно рассматривать как постоянные инструкции, определяющие, как агент работает с вашим кодом.

Хороший файл с правилами должен быть коротким, конкретным и содержать ссылки на примеры, а не их копии:

``` md
# Commands

- `npm run build`: Build the project
- `npm run typecheck`: Run the typechecker
- `npm run test`: Run tests (prefer single test files for speed)

# Code style

- Use ES modules (import/export), not CommonJS (require)
- Destructure imports: `import { foo } from 'bar'`
- See `components/Button.tsx` for canonical component structure

# Workflow

- Always typecheck after making a series of code changes
- API routes go in `app/api/` following existing patterns
```

Чего следует избегать в правилах
    Не копируйте целые руководства по стилю. Вместо этого используйте линтер. Правила должны дополнять ваши инструменты, а не заменять их.
    Не документируйте каждую команду. Агент уже знаком с распространенными инструментами. Добавляйте только команды, специфичные для конкретного проекта.
    Начните с простого. Правила используются в каждом диалоге, поэтому их становится все больше. Добавляйте правила только в том случае, если видите, что агент постоянно совершает одну и ту же ошибку, и делайте их короткими.

# Навыки: динамический контекст

Навыки определяются в файле SKILL.md и могут включать в себя знания предметной области, пользовательские рабочие процессы, а также скрипты и код, которые может выполнять агент.

Правила	Навыки
Загрузка:		Каждый диалог		По мере необходимости
Назначение:		Общие правила и соглашения	Специализированные процессы и задачи
Использование контекста:	Всегда занимает место в контексте	Использует контекст только при обращении
Наилучшее применение:	Что агент должен знать постоянно	Что агент может делать по требованию

MCP: подключение к внешним инструментам
MCP (Model Context Protocol) позволяет агенту подключаться к внешним инструментам и получать соответствующий контекст. Серверы MCP предоставляют агенту доступ к этому контексту и действиям, которые он может выполнять по запросу.

Например, вы можете подключить агента к:

Slack для чтения сообщений и публикации обновлений
Datadog для анализа производственных журналов
Sentry для поиска подробной информации об ошибках и трассировки стека
Базы данных для прямого запроса данных
Figma для получения токенов дизайна и спецификаций компонентов

Инструменты командной строки в качестве возможностей агента
Помимо MCP, агент может запускать любой инструмент командной строки, установленный в вашем терминале. Такие инструменты, как gh, aws, kubectl и docker, работают без дополнительной настройки. Агент может запускать их напрямую.

Укажите агенту на полезные инструменты с помощью правила:


- Use `gh` for all GitHub operations (issues, PRs, CI checks)
- Use `aws s3` for file storage operations
Это также полезно для отладки. Вместо того чтобы переключаться на браузер, чтобы проверить статус CI или найти проблему, вы можете попросить агента: «Проверь, почему CI не прошел проверку этого PR с помощью gh.» Он выполнит команды, прочитает вывод и предпримет соответствующие действия.
