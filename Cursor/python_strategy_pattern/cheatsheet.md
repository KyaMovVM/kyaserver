# 📋 Шпаргалка: Паттерн Стратегия

## Определение (одним предложением)

> **Стратегия** — позволяет менять алгоритмы объекта во время выполнения.

---

## Когда применять?

| Ситуация | Пример |
|----------|--------|
| Много похожих классов, отличающихся поведением | Разные типы уток с разным полётом |
| Нужны разные варианты алгоритма | Сортировка (быстрая, пузырьком, слиянием) |
| Алгоритм использует данные, скрытые от клиента | Шифрование (RSA, AES, DES) |
| Класс содержит много условных операторов | if-else для выбора поведения |
| Поведение должно меняться во время выполнения | Игровой персонаж меняет оружие |

---

## Структура

```
┌─────────────┐         ┌────────────────┐
│   Context   │────────►│ «interface»    │
│─────────────│ has-a   │   Strategy     │
│ -strategy   │         ├────────────────┤
│ +execute()  │         │ +algorithm()   │
└─────────────┘         └────────┬───────┘
                                 │
                    ┌────────────┼────────────┐
                    ▼            ▼            ▼
              ┌──────────┐ ┌──────────┐ ┌──────────┐
              │StrategyA │ │StrategyB │ │StrategyC │
              └──────────┘ └──────────┘ └──────────┘
```

---

## Участники

| Роль | Описание | В примере с утками |
|------|----------|-------------------|
| **Strategy** | Интерфейс для всех алгоритмов | `FlyBehavior`, `QuackBehavior` |
| **ConcreteStrategy** | Конкретная реализация алгоритма | `FlyWithWings`, `Squeak` |
| **Context** | Использует стратегию, делегирует ей работу | `Duck` |

---

## Код-шаблон (Python)

```python
from abc import ABC, abstractmethod

# 1. Интерфейс стратегии
class Strategy(ABC):
    @abstractmethod
    def execute(self, data):
        pass

# 2. Конкретные стратегии
class ConcreteStrategyA(Strategy):
    def execute(self, data):
        return sorted(data)  # пример: сортировка

class ConcreteStrategyB(Strategy):
    def execute(self, data):
        return sorted(data, reverse=True)

# 3. Контекст
class Context:
    def __init__(self, strategy: Strategy):
        self._strategy = strategy
    
    def set_strategy(self, strategy: Strategy):
        self._strategy = strategy
    
    def do_something(self, data):
        return self._strategy.execute(data)

# Использование
context = Context(ConcreteStrategyA())
print(context.do_something([3, 1, 2]))  # [1, 2, 3]

context.set_strategy(ConcreteStrategyB())
print(context.do_something([3, 1, 2]))  # [3, 2, 1]
```

## Принципы проектирования

| Принцип | Описание |
|---------|----------|
| **Инкапсулируйте изменяющееся** | Выделите то, что меняется, в отдельные классы |
| **Программируйте на уровне интерфейса** | Используйте типы интерфейсов, не реализаций |
| **Композиция > Наследование** | HAS-A лучше чем IS-A |

## Плюсы и минусы

### ✅ Плюсы

- Замена алгоритмов на лету
- Изоляция кода алгоритмов
- Замена наследования композицией
- Принцип открытости/закрытости (OCP)

### ❌ Минусы

- Усложнение кода (много мелких классов)
- Клиент должен знать о различиях стратегий
- В Python/JS можно использовать функции вместо классов
