## 🎯 Цель обучения

Понять, как и когда применять паттерн Стратегия для создания гибкого и расширяемого кода.

## 📖 История проблемы: Симулятор уток

Джо работает в компании SimUDuck — делает симулятор уток для игры.
Система использует стандартную ООП-технику: суперкласс `Duck`, от которого наследуются все типы уток.

### Шаг 1: Изначальный дизайн

```
        Duck (абстрактный класс)
        ├── quack()      - крякает
        ├── swim()       - плавает  
        └── display()    - абстрактный (как выглядит)
            │
    ┌───────┼───────┐
    ▼       ▼       ▼
MallardDuck RubberDuck DecoyDuck
(Кряква)   (Резиновая) (Приманка)
```

### Шаг 2: Проблема — нужно добавить полёт!

Руководство решило: "Утки должны летать!"

**Наивное решение:** добавить метод `fly()` в суперкласс `Duck`.

❌ **Результат:** Резиновые утки тоже начали летать! 
   А деревянные утки-приманки даже крякать не должны!

### Шаг 3: Попытка исправления через Override

```python
class RubberDuck(Duck):
    def fly(self):
        pass  # ничего не делает
    
    def quack(self):
        # пищит, а не крякает
        print("Пи-и-ик!")
```

❌ **Проблема:** При добавлении 50 новых типов уток нужно проверять КАЖДЫЙ класс!
   Код становится кошмаром для поддержки.

## 💡 Ключевые принципы проектирования

### Принцип 1: Инкапсулируйте то, что изменяется

> **"Выделите аспекты приложения, которые могут изменяться, 
> и отделите их от тех, которые остаются постоянными."**

Что изменяется в нашем примере?
- `fly()` — разные утки летают по-разному (или не летают)
- `quack()` — разные утки крякают по-разному (или пищат, или молчат)

### Принцип 2: Программируйте на уровне интерфейса

> **"Программируйте на уровне интерфейса, а не реализации."**

Вместо: "утка ИМЕЕТ метод полёта"
Используем: "утка ИСПОЛЬЗУЕТ поведение полёта"

### Принцип 3: Композиция лучше наследования

> **"Отдавайте предпочтение композиции перед наследованием."**

---

## 🏗️ Решение: Паттерн Стратегия

```
    «interface»           «interface»
    FlyBehavior           QuackBehavior
    └── fly()             └── quack()
        │                     │
   ┌────┼────┐           ┌────┼────┐
   ▼    ▼    ▼           ▼    ▼    ▼
FlyWith FlyNo Fly...   Quack Squeak MuteQuack
Wings   Way                  (пищит) (молчит)
```

Теперь `Duck` СОДЕРЖИТ ссылки на поведения:

```
Duck
├── FlyBehavior flyBehavior      ← КОМПОЗИЦИЯ
├── QuackBehavior quackBehavior  ← КОМПОЗИЦИЯ
├── swim()
├── display()
├── performFly()   → flyBehavior.fly()
├── performQuack() → quackBehavior.quack()
└── setFlyBehavior(fb)  ← можно менять на лету!
```

---

## 📐 Определение паттерна

> **Паттерн Стратегия** определяет семейство алгоритмов, 
> инкапсулирует каждый из них и делает их взаимозаменяемыми.
> 
> Стратегия позволяет изменять алгоритмы независимо от клиентов, 
> которые ими пользуются.
